## 后续本地 0.3.19 实现决策

- 字体：核对安装版 ShestakUI 的 Core/PixelPerfect.lua，确认高分辨率会把部分字号乘 mult；其 Chat/ChatTabs.lua 会在悬停时重设字号。采用定向最小字号和目标字体安全后钩子，默认仅 Mac，避免改变正常 Windows 或全局缩放。代价是当前只覆盖已知单位字段与聊天标签，不承诺所有小字；真实 Mac 结果待验。定位 Readability.lua、Options.lua、test_options.py。
- Details：旧 Plan 允许窗口落到视口 38% 附近，可能加重中央遮挡，但不是截图移动源的唯一证据。新 Plan 仅右侧，按 6:4 预算裁完整行；上下顺序采用原上下候选的伤害下/治疗上。通过安装版 Details SetSize/位置接口完成尺寸和行数更新，不改上游文件。代价是极窄右侧空间可能无法安排，64%/62% 保守边界仍需实测。
- 战斗：保护判定针对实际 Details baseframe/rowframe，明确非保护对象才允许纠偏；保护/未知等待脱战。外部移动后合并检查，最多四次修复后停止争抢，避免持续循环。该实现是布局适配，不是绕过安全保护或宣称找到唯一污染源。

## 0.3.20 实测边界替代比例假设（2026-10-21）

状态：用户确认并已实现，模拟验证后仍需游戏验收。背景是 0.3.19 用户截图显示统计上沿高于目标框且侵入图标区域；先前 64%/62% 比例不是用户所需真实边界。

采用目标框下沿、动作条右沿、小地图双列图标预留与底部线计算矩形，宽则等宽并排、窄则等宽堆叠，沿用堆叠 6:4 预算与完整行。依据 SPEC R-015、安装版 ShestakUI Core/Panels.lua（BottomPanel/动作条锚点）、Maps/ButtonCollect.lua（20.8 的图标收集框）及 DetailsLayout/对应测试。保留初始可读宽度以稳定模式；实际按钮优先于编辑器无形占位框。

代价：依赖实际框体名称；未知/限制坐标不能自动摆放。自定义界面无足够宽高仍应提示，而不是突破用户边界。上下/左右顺序沿用当前用户已接受布局，真实皮肤外延、吸附组与自定义插件仍需复测；不修改上游源文件或宣称已完成游戏验证。
