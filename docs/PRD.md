# Cuniel_plus 产品规划与 UI/UX PRD

文档版本：0.3；日期：2026-10-19。

当前插件基线：0.3.17。本文是产品和交互规划；配置窗口整体重构仍是草案，聊天标签功能按下文单独交付。

## 1. 文档定位与状态

- [SPEC.md](SPEC.md) 是已确认的功能规则、默认值和兼容边界。
- 本 PRD 描述用户目标、信息架构、操作流程、状态反馈与界面验收。
- 当前已有功能与已确认规则不因重新设计界面改变。ShestakUI 视觉风格已确认（见 SPEC R-009）；下文导航、尺寸、页面划分和具体交互仍为**待用户确认的设计草案**，确认后才改动游戏 UI。
- 新功能的产品目标、流程与验收写入本 PRD；已确认的长期行为和默认值写入 SPEC；开发执行规则写入 AGENTS.md。详细归档流程见 AGENTS.md“新需求如何归档”。
- 实现限制和测试、发布流程遵循根目录 [AGENTS.md](../AGENTS.md)。用户当前明确指令优先。

## 2. 产品目标

目标用户：以中文界面使用 ShestakUI、多角色切换，希望在保留整套 UI 的情况下获得稳定、容易设置的补充功能。

核心目标：

1. 常用功能能快速找到；添加功能后不把设置窗口越堆越长。
2. 能直接看懂哪些功能开启、哪些按账号共享、哪些仅影响当前角色。
3. 背包物品能看出其他角色和战团银行的数量，但不被炉石、垃圾或身上装备等低价值统计干扰。
4. 能调整背包装备部位的字号、品质范围，并获得清楚的状态反馈。
5. 遇到数据缺失、需要重载或战斗限制时，有明确原因，不以刷屏或无限等待掩盖问题。
6. 更新插件后能知道这版具体改了什么、适用哪一版游戏，已有设置保持可理解且可恢复。

非目标：重做整套 ShestakUI、强制替换用户 UI 布局、解决所有上游插件错误、绕过战斗保护，或把未读取的账号库存称作实时完整数据。

## 3. 当前体验问题

已确认的本地化方向：改善中文排版与数字单位一致性，不重复做简繁翻译；DoT、HoT 等术语保留。语言与地区是不同维度，地区适配不能以改语言代替。具体扩展模块仍待逐项评估。

以下是对现有实现和聊天反馈的整理，不代表每项都已有独立游戏实测：

| 问题 | 对用户的影响 | 设计方向 |
| --- | --- | --- |
| 设置窗口持续变高，包含多个不相关模块 | 选项难找，小屏幕或大缩放时更难操作 | 固定外框、分类导航、页面内滚动 |
| 品质、字号、模块开关分散 | 不清楚哪些选项共同影响一个效果 | 同功能的选项放在同一组 |
| “缓存”“账号共享”“当前角色”容易混淆 | 对数量准确性或开关作用范围产生误解 | 在功能说明附近简明标注 |
| 物品统计与上游原有数量行同时存在 | 容易误判过滤没有生效 | 新增区清楚命名，说明过滤范围 |
| 战斗中关闭窗口被拦截 | 容易认为所有 ESC 兼容都失效 | 区分窗口未登记与战斗限制 |
| Release 曾仅有比较链接 | 时间久后难以知道每版改动 | 持续维护逐版中文更新说明（已落实） |

## 4. 信息架构草案

建议采用左侧分类、右侧内容的单窗口布局；不为每个新功能增加独立大窗口。分类属于草案，尚未获得用户对导航形式的确认。

| 页面 | 内容 | 页面内推荐分组 |
| --- | --- | --- |
| 总览 | 当前版本、适用游戏、主要模块状态、常用入口 | 版本与更新、快捷入口 |
| 背包与银行 | 背包位置、Bagnon 工具条、整理、自动售卖、战团存放 | 背包布局、整理与售卖、战团存放保护 |
| 物品提示 | 多角色数量、缓存说明、统计过滤、装等显示 | 角色物品数量、过滤规则、装等提示 |
| 文字与显示 | 数字格式、FPS、装备部位文字 | 数字格式、帧数、装备部位字号与品质 |
| 兼容与诊断 | ESC 兼容、静默、竞技场重复消息、诊断入口 | 窗口兼容、消息、问题诊断 |

原则：同一设置只有一个正式编辑位置；其他页面可有跳转入口，不复制一个可能不同步的开关。

## 5. 页面与关键流程

### 5.1 通用设置行为

- 入口继续使用 `/cplus`、`/cuniel` 和游戏插件设置入口。
- 普通复选框、字号、品质选择即时生效；需要重载的操作在按钮文字或说明中直接写明。
- 账号设置标注“账号共用”，ShestakUI 自动售卖标注“当前角色”。不能为了统一外观而改变底层作用范围。
- 主功能关闭时，保留其参数。相关子项可禁用并显示原因，而不是删除用户选择。
- 页面切换保留尚未保存的 ID 输入，或明确提示输入未保存；不得切页后无声丢失。
- 不为普通设置加入重复确认。会重置已保存配置或丢弃输入的操作，先清楚说明具体影响。
- 提供针对单个功能的恢复默认方案，不把“恢复默认”解释成清空所有角色缓存或整个 WTF。

### 5.2 装备部位文字

用户流程：进入“文字与显示” → 装备部位 → 开启显示 → 调整字号 → 选择显示哪些品质 → 在背包直接查看结果。

需要同组呈现：

- 总开关。
- 字号（当前 8–24、默认 11）及即时文字预览。
- 完整品质列表，色块与名称同时显示，不只依赖颜色。
- 默认灰/白/绿关闭、蓝色及以上开启；用户可逐项改变。
- “非装备不显示部位”的简短说明。

预览为样例时必须标注“预览”，不能伪装成从背包读取到的真实装备数据。品质名称、默认值、未知数据处理以 SPEC 的 R-031 为准。

### 5.3 物品数量与过滤

用户流程：悬停物品 → 查看职业色角色名与数量 → 如信息无用，进入过滤设置调整 → 重新悬停确认效果。

提示框的建议顺序：保留原物品内容 → Cuniel_plus 角色统计标题与合计 → 各角色 → 战团银行。

- 统计保持在原提示框内，不新开独立黑框。
- 保留角色职业色；跨服重名带服务器。数量对齐，战团银行只计一次。
- 缓存性质在标题或相邻说明中可见，不对每一行堆叠相同长说明。
- 过滤组中同时提供炉石、已穿装备、垃圾、可选任务物品与 ID 名单；保留当前默认值，不把“绑定”当成全部隐藏的条件。
- ID 名单保存成功给一次简短反馈；非法输入保留旧名单并指出格式要求，允许清空。
- 银行存放保护的排除名单与统计隐藏名单分开命名，不能用同一个“白名单”按钮指代两者。
- 已过滤导致本模块数量为零时，不添加空的角色列表。缓存范围不足不能当作“所有角色都没有”。

### 5.4 背包与银行操作

- 默认背包避让右侧动作条和下方 Buff，行为以 SPEC 为准；不能为了排版重新移动玩家头像、施法条等无关组件。
- 已接管 ShestakUI 战团存放时保留可识别的提示，用户能知道食物保护与保留 ID 是否适用。
- 整理、存放按钮区分用途，鼠标提示说明左右键行为。按钮样式与 ShestakUI 协调。
- 战斗、离线展示、银行不可操作或整理中不允许执行时，应说明对应条件；不能看起来成功但没有执行。
- 数量读取、品质文字等只读功能不抢占右键或自动操作背包物品。

### 5.5 装等显示与修复

- 正常查看玩家时，装等位于原提示框内部，沿用现有 ShestakUI 风格。
- 当前功能与 ShestakUI 原生平均装等冲突时，页面说明“由 ShestakUI 显示”，提供当前已实现的切换修复入口。
- 切换按钮明确会“切换并重载”；不能让用户误以为仅调外观。
- 数据未取得或不可查看时，不无限追加“等待中”。不要把仍在等待的值展示为 0 装等。

### 5.6 诊断体验

- 清楚区分：功能关闭、未登记窗口、战斗限制、第三方调用被拦截、数据未采集。
- 将 `/cplusesc`、`/cplusdiag` 对应的用途用中文描述；是否增加界面按钮和可复制文本框，留待实现阶段确认。
- 可以展示已捕获的插件名和操作，但不把它渲染成“确定唯一责任插件”。
- 静默不隐藏诊断错误来伪装已修复；不把报错次数直接解释为网络掉线原因。

## 6. 状态文案原则

下表是建议文案方向，具体短句可在实现时微调，不更改事实含义。

| 状态 | 应表达的信息 | 避免 |
| --- | --- | --- |
| 模块关闭 | 已关闭，参数已保留 | 清空参数或误报插件未安装 |
| 离线数量 | 上次已记录的缓存数量 | “全账号实时库存” |
| 尚未读取银行 | 打开对应银行后更新 | 显示为确定的零数量 |
| 战斗限制 | 脱战后再执行 | “已永久失效”或无限重试 |
| 未加载依赖 | 需要的插件尚未就绪 | 点击后无反馈或 Lua 错误 |
| 上游接管装等 | 当前由 ShestakUI 显示 | 重复装等行或外置黑框 |
| ID 输入错误 | 正整数 ID，用空格/逗号分隔；旧名单保留 | 丢弃旧名单或接受错误值 |
| 需要重载 | 按钮直接说明“并重载” | 点击后突然重载而无事先说明 |

## 7. 视觉与可用性草案

- 与 ShestakUI 协调：深色背景、紧凑边框、清楚标题、有限强调色；不把所有控件做成同样醒目的大红按钮。
- 普通文字要易读，正文和标题有层级；FPS 和装备部位字号保持独立，不把某一项字号当作全部 UI 字号。
- 分类窗口不再随模块增加而无限增高；内容长时在右侧区域滚动。
- 首轮建议固定大小约 680×560（UI 单位），之后按用户分辨率与 UI 缩放实测调整；这是候选尺寸，不是已批准硬性尺寸。
- 支持移动和屏幕边界约束；关闭重开后不应跳到用户无法操作的位置。
- 所有品质同时有名称与颜色；选中/禁用状态清晰可辨，按钮和文字不重叠。
- 过滤设置修改后不强制重载，不在聊天区连续刷多条成功提示。

### 8.1 首版视觉方向 A（已被 B 的风格方向替代）

- 左侧五分类，当前示例为“文字与显示”，页内数字格式、帧数、装备部位三个页签。
- 深灰底、细边框、金色标题/选中状态；按钮紧凑，不沿用大量大红按钮的堆叠。
- 装备部位的总开关、账号共享标记、字号滑块及输入框、完整品质列表、样例预览同页呈现。
- 预览展示蓝色脚部、紫色手指与绿色装备隐藏部位的区别；示例不代表真实背包数据。
- 底部显示设置保存状态，恢复默认仅作用当前页。
- 搜索、页内预览、恢复本页默认等仍是视觉提案，不代表当前 0.3.16 已实现。

设计参考（2026-10-18 查阅，借鉴组织方式，不复制现有界面）：

- [ElvUI 官方选项目录](https://github.com/tukui-org/ElvUI/tree/main/ElvUI_Options)：模块化选项组织。
- [WeakAuras 官方 Custom Options](https://github.com/WeakAuras/WeakAuras2/wiki/Custom-Options)：分组、控件、说明和留白，避免过深嵌套。
- [Details 官方发布图库](https://www.curseforge.com/wow/addons/details/gallery)：WoW 插件内的紧凑信息呈现；不是配置窗口的逐项复刻。

设计稿通过内置 imagegen 生成，用户在本轮对话查看。确认方案前只存为设计资产，不改游戏运行时代码。

### 8.2 ShestakUI 风格稿 B

- 已确认：沿用 ShestakUI 风格（SPEC R-009），采用半透明黑色背景、细边框、方形控件和其按钮皮肤；具体颜色与职业色读取实际 ShestakUI 配置，不把示意图中的圣骑士粉色固定给所有角色。
- 图中黄色标题、粉色选中态是视觉示例，最终游戏效果由可用皮肤及媒体配置决定。
- 分类布局、装备部位页、字号与品质设置同页、预览区等仍为待确认设计，不改变现有功能默认值。
- 图稿已在对话展示，并在本地保存为 `docs/design/settings-concept-b.png`；图片尚未上传仓库，GitHub 不提供该路径下载。[生成记录](design/settings-concept-b-prompt.md)保留完整提示词。图稿用内置 imagegen 编辑生成，不是游戏内实测截图。
- 该图用于确认方向；只有用户明确确认的内容才转为正式规格与实现任务，不能把图片中的文字当作新的产品要求。

### 8.3 数字单位统一扩展（已确认，优先待实现）

用户于 2026-10-19 再次明确不能遗漏。关联 SPEC R-010：除公共数值函数外，独立检查并适配血量、伤害、治疗、经验、声望等模块；包括底部信息栏自行计算的 K/M/B 格式。目标提供万/亿、K/M/B 与完整数值选择。当前的“跟随 ShestakUI”不能冒充完整数值模式。

实施前建立覆盖清单：每个位置记录原格式化路径、是否使用公共函数、受保护数值限制、预览样例和验证状态。重点检查姓名板/单位/团队血量、自带伤害治疗文本、LiteStats 经验/声望及数值提示；发现独立格式化代码则单独适配，不做全文 K/M 字符串替换。第三方插件如 Details 仍须独立适配，不能宣称已被公共函数覆盖。

验收包括：同一数值在目标模块采用一致的单位进位与精度；完整模式无缩写；零、负数、单位边界、极大值行为明确；中文单位不被截断；受保护数值不直接计算；能够恢复原插件模式。具体精度和拥挤场景排版在实现阶段确认。

状态：0.3.17 未实现该扩展，不计入聊天标签发布的完成范围。

### 8.4 中文聊天标签（0.3.17，已实现，待游戏实测）

目标：新角色不再手工创建同样的标签，同时避免已有英文/中文自定义页重复；参考 Ciaoasher 的分类，不复制账号私有资料。

流程：安装并启用插件 → 登录角色 → 脱战且聊天窗口就绪 → 备份并清理永久自定义标签 → 保留内置页并创建“公会、密语、团队” → 记录本角色已初始化。后续登录只检查标记，不重复创建。

设置入口：`/cuniel` → “聊天标签页”。显示总开关、首次清理范围与备份说明、当前状态；提供主动重建与恢复原标签两个操作。恢复后停用当前角色自动初始化，不影响其他角色；总开关账号共用。规则以 SPEC R-014 为准。

验收：旧标签不残留为重复页；综合/战斗记录/内置语音及临时会话不被关闭；公会、游戏内/战网密语及小队/团队/副本消息分类正确；重复登录无新增；跨角色分别初始化；备份可恢复；战斗及接口缺失不破坏现有标签。源码与 Lua 模拟验证单独记录，不等于游戏实测。

该功能属于独立补充，不代表本 PRD 的导航美化已实现或确认。

## 9. UI/UX 验收

- 从设置入口能找到部位品质、数量过滤、战团存放保护和诊断，名称不混淆。
- 普通设置切换即时生效，需重新悬停或重载时有清楚说明。
- 账号/角色作用范围、缓存含义明确，数量与过滤语义符合 SPEC。
- 小屏幕或较大 UI 缩放下，关闭按钮、主要控件和滚动区域仍可操作；无文字或按钮重叠。
- 保持物品右键、提示框刷新和脱战保护行为；不能为了新 UI 回归曾出现的无限刷新或物品无法使用。
- 旧配置升级后仍可读取，不要求用户重新配置全部功能。
- UI 模拟/截图验证与真实游戏测试分别记录；发布说明写明具体完成和未验证的范围。
