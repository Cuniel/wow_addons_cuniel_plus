# Cuniel_plus 产品与开发规格

状态：包含 0.3.21 本地实现及待验证要求；更新于 2026-10-21。

Details 补充确认：选中/清除目标不应改变统计窗布局。目标、相邻头像和目标的目标按已布置坐标提前预留；相邻允许最多 16 UI 单位间距，保持原 8 UI 单位安全边距。目标相关框体显隐本身不释放空间；真实锚点/尺寸/分辨率变化仍重算。受限制/未知坐标时等待，不强行计算。

本文件维护功能行为；实际架构见 [ARCHITECTURE](ARCHITECTURE.md)，当前实现/验证与 Git 状态见 [HANDOFF](HANDOFF.md)，执行与授权流程见 [AGENTS](../AGENTS.md)。最新确认需求不能冒充现有代码或游戏验证结果。

用途：让后续开发者和 AI 无需完整聊天记录，也能理解用户要什么、哪些行为不能随意改变。这里的“要求”不表示每种游戏场景都已实测；当前实现、模拟验证和用户反馈需要分别说明。

UI/UX 规划另见 [PRD.md](PRD.md)。其中未确认的新界面方案不改变本规格的默认值，也不表示已实现或已授权本轮重构。

## 1. 项目范围与决策

### R-001 独立增强插件

- 插件名 `Cuniel_plus`，模块化扩展，以 ShestakUI 增强为主，也兼容已有 Bagnon 使用场景。
- 增强放在 Cuniel_plus 内，不直接修改 ShestakUI、Bagnon 或 GearView 源文件；上游更新应能正常进行。
- 设置入口 `/cplus`、`/cuniel`；模块应能单独开关，设置默认账号共享。复用上游按角色保存的设置必须明确标注，例如自动售卖。
- 玩家能用中文设置理解功能，不必知道 Lua 接口名称才能操作。保留已有设置和缓存，更新不要求清空 WTF。

### R-002 沟通边界

- 用户明确说“先聊”“先分析”“先排查”时，先做讨论或只读诊断，不直接实施设想。
- 不清楚的产品规则、默认值及是否改变已有行为，向用户确认；不要反复确认已经授权的普通实现、提交、打包。
- 当前明确指令优先于旧规格；确认变化后更新此文档。未确认事项保持在第 8 节，不能当成已批准任务。

## 2. 界面与基础功能

### R-009 配置界面视觉一致性

- 用户于 2026-10-18 确认：Cuniel_plus 是 ShestakUI 增强，配置界面的配色、边框和控件风格沿用 ShestakUI。优先复用其可用皮肤与媒体配置，避免另做一套独立品牌配色。
- 具体页面布局、预览区、控件尺寸等由 PRD 规划；颜色风格确认不等于所有布局细节已确认或功能已实现。
- ShestakUI 不可用时的备用视觉方案仍待设计，不在此承诺未经验证的效果。

### R-010 数字格式

- 针对 ShestakUI 的统一数字格式，支持万/亿四位进位、K/M/B 三位进位和跟随原插件；默认万/亿。
- 不是全游戏所有插件数字的全局替换，不能宣称会改变 Details 等所有数值。
- 可能受保护的数值交给适当的游戏格式化接口，不直接运算不可访问的战斗数据。
- 2026-10-19 确认的优先扩展：逐项覆盖血量、伤害、治疗、经验、声望，包括自行格式化数值的底部信息栏模块；不能只替换公共 ShortValue 就宣称已统一。
- 扩展目标提供万/亿、K/M/B 和完整数值选择。当前实现仍是万/亿、K/M/B、跟随原插件，尚无独立“完整数值”模式；跟随原插件不等于完整数值。覆盖扩展与完整模式列入 PRD 优先待实现，不属于 0.3.17 已交付内容。

### R-011 FPS

- 默认关闭、字号 14，支持字号、开关、拖动位置、锁定鼠标穿透及重置位置。
- 边框紧凑，允许靠近屏幕底部；位置账号共享并保存。不要以原生 Ctrl+R 显示代替这个功能。

### R-012 职业色与背包避让

- 金币统计和角色物品数量中的角色名使用已知职业颜色；未知职业不根据名字猜测。
- ShestakUI 背包位置以其原始锚点为基准，默认左移 55、上移 40，避免右侧动作条和下方 Buff；重复打开不能累计偏移，关闭开关恢复原始基准。

### R-013 中文与地区适应性方向

- 定位是改善中文排版、数字单位及地区使用习惯，而不是宣称 ShestakUI 没有中文翻译。现有简繁翻译和中文字体适配应优先复用。
- 重点是中文排版适应性和数字单位统一；DoT、HoT 等常用术语无需翻译。客户端语言与游戏地区分别判断，不能由中文客户端推定国服。
- 具体排版模块与新增数字覆盖范围仍需逐项规划和验证，不因这个方向而自动重写所有插件。

### R-014 中文聊天标签初始化

- 2026-10-21 确认：公会/密语/团队三个标签**标题**默认 14 号，账号共享独立字号 10–20，Windows/Mac 共用；不是聊天正文的字号，不改普通标签。已有角色不重建，仅更新标题；悬停后保持选择，通用小字补偿对这些标题让位。关闭聊天功能或恢复原标签时可恢复会话原标题字号，战斗中延后，保留备份及消息分类。

- Cuniel_plus 独立提供，不称为 ShestakUI 自带功能。参考本机 Ciaoasher 的聊天分类配置；不复制其账号标识、服务器频道、窗口坐标或聊天内容。
- 默认启用，新账号/角色只要启用插件即可使用，无需读取 Ciaoasher 角色文件。账号共享总开关，初始化标记和原配置备份按角色保存。
- 保留综合、战斗记录及游戏内置语音窗口。首次应用前备份并清理已有永久自定义聊天标签，再按参考顺序创建“公会、密语、团队”，避免保留英文/旧中文重复页。
- 公会：公会、官员、公会成就；密语：游戏内和战网密语；团队：小队、小队队长、团队、团长、团队警告、副本和副本队长消息。
- 不从综合中移除既有消息类别，也不退出已加入的世界/寻求组队等频道。清理的是自定义窗口，不是账号的聊天频道订阅。
- 成功后每角色只初始化一次；再次登录、重载和切地图不删除重建，也不持续覆盖用户后续调整。需要重置时由用户主动重建。
- 内置和临时会话窗口不清理；窗口容量不足或必要接口缺失时不修改现有标签。战斗中延后到脱战；中断失败不标记成功、不自动循环刷屏。
- 提供恢复原自定义标签并停用当前角色自动配置的入口。备份保存标签名称、消息类别、频道及基本布局设置，不保存聊天消息/输入历史，不能承诺恢复已关闭窗口的会话记录。
- 关闭总开关不删除已创建标签；主动重建不覆盖首次备份。使用当前角色聊天字体并接入已有 ShestakUI 聊天皮肤，不把参考角色字体与坐标强加到所有角色。

### R-015 Details 分辨率与布局适配

以下原条目保留 0.3.18 的行为及设计依据，0.3.19 更新以上述条目之后的“当前实现”段为准，不把历史限制当作当前算法。

- 在 Cuniel_plus 内补充，Windows 与 Mac 共用，不修改 Details 或 ShestakUI 文件，不把重叠一律归因于低物理分辨率。
- 默认开启，针对首个可见伤害和首个可见治疗窗口。使用窗口实际有效缩放换算到同一 UIParent 坐标，计算皮肤/标题边距；布局正常时保留用户位置，不固定为某个分辨率的像素坐标。
- 两窗重叠、越界或遮挡已识别的小地图、动作条、玩家/目标框架时，尝试并排；横向空间不够则尝试上下排列。其他可见统计窗作为障碍，不任意重排所有实例。
- 不通过缩小字号、隐藏数据或缩放整个 UI 解决。空间仍不足时保留当前位置并提示手动留出空间；不承诺所有自定义面板、吸附组或额外插件均已覆盖。
- 登录、分辨率/UI 缩放变化、Details 加载/窗口显示和尺寸变化时合并检查，不逐帧抢位置；战斗中延后，鼠标拖动中不移动。
- 提供开关及主动重新排列。仅在实际移动前保存当前会话的原位置，关闭时恢复；不承诺关闭后跨重载恢复此前未备份的位置。位置通过 Details 自身接口保存，不修改其统计内容、字体和分组配置。
- 用户已明确暂缓 Mac 字体适配，等待其后续采集；本版不改 Mac/Windows 字体配置。

2026-10-20 更新：上述为 0.3.18 现有算法，用户 Mac 实测仍遮挡，战斗时移到中央的调用来源待查。用户新确认按统计区实际可用高度上下排列，伤害占 60%、治疗占 40%，通过减少可见行数适配，不缩字号、不丢失统计数据；这允许调整窗口高度，替代原算法保持尺寸的策略。具体边界、上下顺序和极小空间的行数取整需在实现时核对，当前尚未实现。

用户补充 Mac 样本：此前报告 3600×2260，新截图 UI 缩放约 0.782、mult 约 0.50005、单位字号约 8.00079、标签字号约 9.00089。这是用户截图数据，不是本轮读取客户端或已定位字体根因。用户随后确认可继续修改三项 Mac/Details 问题的代码和测试，不再将字体工作无限暂缓；实现与验证状态记入 HANDOFF。

当前实现（本地 0.3.19，模拟通过、游戏待验）：伤害在下、治疗在上，按右侧可用高度的 60%/40% 预算扣标题并取整完整行；不缩字号、不删除统计内容。只在右侧候选区间安排，不向中央找空位；不足各一行时保留并提示。外部位置/缩放和进出战斗合并检查；明确非保护统计窗允许战斗纠偏，保护/未知则延后。持续冲突最多四轮停止争抢；关闭后脱战恢复会话内原位置与尺寸。当前右侧候选和极小空间行为属于实现边界，真实布局验收不能省略。

R-015 最新确认与实现（2026-10-21，0.3.20）：Details 上沿不得超过目标框下方（相邻头像/目标的目标一并避让），左侧不得覆盖实际技能栏，右侧在小地图左边预留两个小图标列，底部可以到信息线之上。读取实际框体和有效缩放，不能继续用视口百分比代替；目标隐藏后仍按布局锚点测量，必要坐标不可用则等待。宽度足够时伤害左/治疗右等宽并排，不足时伤害下/治疗上等宽堆叠；堆叠保留 6:4 高度预算。两种模式总高度均在同一边界内，按完整行调整，不缩字号。此段替代上版“仅堆叠、64%/62%”的实现限制；真实游戏复测仍需完成。

R-015 右对齐补充（2026-10-21 确认，0.3.21）：以可用区最右边界为基准，先确定右侧治疗窗，伤害等宽紧邻左侧，窗间距 2 UI 单位，不拉宽铺满剩余空白。宽度不足则等宽堆叠并对齐右边缘，保持总高度和四边界；不以手动旧位置代替可用区右边界，也不为容纳窗口向左越过障碍。

### R-016 分类配置窗口

- 用户要求 `/cuniel` 展示新的配置界面，0.3.18 实现左侧五分类：总览、背包与银行、物品提示、文字与显示、兼容与诊断；文字与显示内分数字格式、帧数、装备部位。
- 沿用可用的 ShestakUI 深色皮肤、按钮和复选框；窗口可拖动、可用 ESC 关闭，较小可用区域自动适应边界，长内容在页面内滚动。
- 所有旧设置和模块入口保持可访问，不重置用户选择；装备部位的开关、字号和全部品质同页，提供简单文字预览。
- 不将设计图里的搜索、独立图标预览或恢复本页默认宣传为已交付；实际版本按本规格和 Release 说明验收。未来数字覆盖扩展和 Mac 字体适配保持独立规划，不因换 UI 而虚报完成。

### R-017 高分辨率字体可读性（0.3.19）

- 在“文字与显示 → 字体可读性”提供开关、仅 Mac 限制和最低字号；默认开启但仅 Mac 且 ShestakUI mult < 0.85 时生效，最低 12，可调 10–20。Windows 默认不变，也可主动取消平台限制。
- 定向补足已知单位文字和聊天标签，不缩小原本较大字号，保留字体与描边，不改变 UIParent 缩放或上游磁盘文件。FPS、装备部位、Details 字号不受此开关控制。
- 战斗中字体调整等待脱战；悬停时上游重设聊天标签字号仍可定向补偿。关闭恢复当前会话原字体状态；其他插件后来修改的字体不盲目覆盖，不宣称所有中文排版问题已解决。

## 3. 背包整理、售卖和战团存放

### R-020 整理以最终确认的 ShestakUI 原版规则为准

- 最终确认：移植 ShestakUI 的原版整理键与顺序，从后向前摆放，不额外给炉石写“优先放最后”的特例。
- 早期讨论过按大版本、专业材料、BoE 等自定义分组；后来用户选择原版整理。这些旧设想不得在后续“优化”中自动恢复。
- 普通包、材料包和特殊用途包须保持兼容性；个人银行不与战团银行互相搬运。仅处理当前可操作范围，不能操作离线展示。
- 关闭窗口、切换仓库或进入战斗时停止物品移动；整理过程有再次点击停止的能力。缓存未准备好应有限等待/重试，不反复刷屏或无限循环。
- 当前 Bagnon 适配使用外部工具条；不应为加入功能而重写其物品点击或反复主动触发布局。

### R-021 自动售卖

- 在 Cuniel_plus 设置内提供开关，即便 Bagnon 替代 ShestakUI 背包也可使用。
- 复用 ShestakUI 当前角色的自动售卖设置，开关标注“当前角色”，在下次商人交互时生效。

### R-022 战团存放保护

- Bagnon 工具条和已接管的 ShestakUI 战团存放按钮应使用 Cuniel_plus 的保护规则。
- 默认保留游戏分类为食物/饮料的物品，并允许用户填写不存入战团的物品 ID。用户称“白名单”，这里实际语义是保留在背包中的排除名单。
- 未取得必要分类时保守保留，不把未知物品误存入。默认 ID、后续用户修改和缓存不得每次更新重置。
- 是否包含制作材料复用游戏设置。物品移动只在实际可用银行和用户按钮点击路径进行，拒绝战斗、整理中、离线展示等不适用状态。
- 数量统计的隐藏名单与存放名单相互独立，不能混用。

## 4. 装等、装备部位与物品数量

### R-030 鼠标装等

- 装等合并在现有物品/单位提示的对应玩家提示框内，沿用 ShestakUI“物品等级”黄色标题、数值相对颜色和一位小数；不用独立黑色页脚。
- 有装等数据才显示，不反复添加“等待中”倒计时、不无限追加、不递归 Show、不逐帧重建提示。
- 当 ShestakUI 原生平均装等仍启用时让位。为其重复提示问题保留用户主动点击的切换修复：修改当前持久配置、启用 Cuniel_plus 装等并重载，不尝试在运行时强拆它的私有脚本。
- 检查请求有节流、缓存和悬停目标核对；不在战斗或游戏不允许时强行请求，不显示受限制数据。

### R-031 装备部位文字

- 由 Cuniel_plus 独立显示在 ShestakUI 背包/银行装备格底部；鼠标悬停不应使文字消失。
- 不依赖 GearView，不接管物品按钮的右键、OnEnter/OnLeave 或装备使用流程。
- 字号独立可调，当前范围 8–24、默认 11；设置账号共享、修改即时刷新。
- 从 0.3.16 起按品质逐项控制，默认如下：

| 品质 ID | 品质 | 默认显示部位 |
| --- | --- | --- |
| 0 | 粗糙／灰色 | 否 |
| 1 | 普通／白色 | 否 |
| 2 | 优秀／绿色 | 否 |
| 3 | 精良／蓝色 | 是 |
| 4 | 史诗／紫色 | 是 |
| 5 | 传说／橙色 | 是 |
| 6 | 神器／金色 | 是 |
| 7 | 传家宝／浅蓝色 | 是 |
| 8 | 时光徽章／特殊品质 | 是，但非装备无部位可显示 |

- 用户说“精良（蓝色）及以上”，因此绿色也默认不显示；不能误解为仅灰、白关闭。
- 只给可穿戴装备显示部位；非装备不因勾选品质而增加文字。品质未知或不可读取时隐藏，数据就绪后重试。
- 首次升级增加品质字段时补上述默认值，后续不能每次启动覆盖用户自己的品质选择。

### R-032 战团物品数量

- 在原提示框内列出职业色角色名与数量，战团银行单列并且仅计一次；无需持续启用 Bagnon。
- 独立缓存每个角色背包、材料包、装备和已读取个人银行，以及账号战团银行。已有运行时 BrotherBags 数据可导入，但不能宣称停用后还能任意读取其磁盘缓存。
- 登录、背包/装备变化、可用银行数据变化时更新。离线数量是缓存；未登录角色或未打开银行不代表真实数量为零。明确标注缓存性质，不称为服务器全账号实时总量。
- 不统计邮箱、公会银行或已装备背包本身；角色跨服务器同名时带服务器区分。当前按数量降序列出有数量的角色。
- 默认排除炉石 6948、要塞炉石 110560、达拉然炉石 140192，以及灰色垃圾。
- 默认不把穿在身上的装备计入数量；同款物品在背包或银行仍可计数。保留原缓存，让用户关闭过滤时能恢复计数。
- 任务物品可选择隐藏，默认保留；绑定装备目前保留，不一刀切排除所有灵魂绑定材料、兑换道具。
- 提供独立的物品 ID 隐藏名单；输入无效不能毁掉旧名单，允许清空名单。
- 过滤只作用于 Cuniel_plus 新增统计区；ShestakUI 原“物品数量”一行仍可存在，不得把这行当成本模块过滤失败。
- 同一提示框生命周期中去重，不为统计接管物品按钮、自动使用物品或额外请求装备检查。

## 5. 静默和 ESC 兼容

### R-040 登录静默与竞技场刷屏

- 静默只处理已识别插件的启动、加载、宣传消息，不清空正常聊天，不以隐藏报错当成修复。
- 竞技场过滤只针对短时间重复的“玩家加入战斗”消息，保留首次提示及其他系统消息。过滤结果不证明源插件或上游事件问题已修复。

### R-041 ESC 窗口

- 允许常用顶层窗口用游戏 ESC 机制关闭，支持按需加载、避免重复登记，关闭功能仅移除自己新增条目。
- 当前包含地图、飞行地图/旧路线图、角色（含货币/声望）、天赋/专精/法术书、专业、收藏、冒险指南等明确窗口，详见 `Modules/MapEscape.lua`。
- 不劫持全局 ESC，不盲目把所有 Frame、交易窗口、确认弹窗或嵌套编辑器放入名单。
- 已确认：用户战斗中 `PlayerSpellsFrame:Hide()` 被拦截，脱战后可关闭。不能把这类问题误判为再补登记就能解决，更不能绕过保护。
- 保留 `/cplusesc` 和 `/cplusdiag` 的诊断用途，报告加载版本、状态或实际操作拦截，不宣称诊断命令会修复所有污染。

## 6. 稳定性与验证

### R-050 验证边界

- 游戏 12.x 可能返回 secret 值，须在比较、表索引、计算、拼接或格式化前确认可读取；未知时跳过/等待，不猜测。
- 不无限请求检查、重建提示、追加行或移动物品。事件触发与有限合并刷新优先；避免为只读展示改写游戏公共物品使用接口。
- 读不到银行时保留旧快照，可读取的空银行应清除旧数量；离线角色不能误用当前角色实时数据。
- 模拟测试覆盖本次行为及相关旧行为。最终说明必须区分：源代码核对、模拟测试、用户实测与尚未验证，不把模拟器当成游戏安全执行环境。
- 按事件时间核对报错。累计次数可能跨多次会话；被标记插件名不等于唯一根因；不能从 Lua 错误直接断言网络掉线原因。

## 7. 版本管理与发布

### R-060 源码与仓库

- 唯一仓库：https://github.com/Cuniel/wow_addons_cuniel_plus；插件目录 `Cuniel_plus/`。
- 每次功能/修复提交应具体说明问题与结果，保存可回退的版本历史；不要继续维护多个 outputs 源码副本。
- 用户已要求通过此仓库维护和自动发布，常规提交、测试和发布按该授权执行；不因此推定可以修改其他仓库或插件源文件。
- 上条保留历史背景，不能直接推定长期授权仍有效。当前文档及随后明确的 Mac/Details 修复任务均不提交、推送或发布；长期条文调整待用户另行确认，见 AGENTS/HANDOFF。

### R-061 客户端版本来源

- 发布前读取实际安装的正式服版本，优先核对 `.build.info` 中 active 的 wow 产品和 `_retail_/Wow.exe` 版本；必要时核对游戏 `GetBuildInfo()` 的接口号。
- 不根据美服更新时间或“最新版本”猜测国服版本。TOC Interface 与文档中的兼容声明应一致。
- 整理此规格时的开发基线：国服正式服 **12.1.5.70448**，接口 **120105**；当前 TOC 同时声明 **120100 / 120105**。这不是永久固定的后续版本号，也不代表全功能实测。
- 历史版本未记录精确构建号时明确注明，不把今天的构建号补成过去的实测记录。

### R-062 用户能看懂的逐版更新说明

- README“本次更新”只写当前具体版本的实际变更，包含插件版本、适用客户端、构建/接口及来源；整体功能和历史更新分开。
- `CHANGELOG.md` 保存逐版汇总，`release-notes/v<版本>.md` 是对应 GitHub Release 正文来源。
- Release 必须有中文具体更新、适用范围、安装/设置方法，不能只显示自动生成的 Full Changelog 比较链接。
- 功能发版同步 TOC、设置窗口版本、README、CHANGELOG 和对应 Release 说明。未写说明应阻止发布。
- GitHub Actions 测试通过后打包并创建 Release，确认正文和 ZIP 链接可用。已有 Release 的说明可补正，不能悄悄覆盖同版本 ZIP 或历史代码。
- 纯规格/说明变更且插件包内容不变时，不为此要求用户重新安装；文档提交本身不必制造一个新插件版本。
